# Problem Definition
---
#### From Use Case to Business Justification

> A use case names an opportunity. A business case brief names a decision, the person who makes it, and a finish line.

| #   | Element              | Prompt                                          | Our answer |
| --- | -------------------- | ----------------------------------------------- | ---------- |
| 01  | Sponsor and priority | The L0/L1 priority, in the sponsor's words      |            |
| 02  | Decision             | The recurring decision v1 will improve          |            |
| 03  | Decision maker       | One named role who makes it                     |            |
| 04  | Users and SMEs       | Who uses the solution; who the pod shadows      |            |
| 05  | Current state        | How it's done today, and why it's suboptimized  |            |
| 06  | Success and baseline | The measure, today's number, and the end target |            |
| 07  | Scope                | What's in v1, and what's explicitly out         |            |
| 08  | Constraints          | Data access, governance, and sponsor guidance   |            |
