# Meeting Planning for Cisco Update

---

- Implement a `HOLD` with reason `Response Received` for all update communications
    - You will see a notification next to the email tab on the far right
    - You will also see HOLD status

- Expectation is you put status to work before you open the request - **SHOW THIS**

## Walk through expectations

- Open a queue:
    - **NEW** Means that a request has not yet been claimed - first email
    - **WORK** Means someone has claimed it and has begun work on the request
    - **HOLD** Means that Triage has detected a new response and has added it to RC

- Expectations for **NEW**
    1. Change status to `WORK` and open the request
    2. Read the summarized note
    3. Read the email in `emails` tab if needed
    4. Review any attached files if necessary
    5. Move the request forward

- Expectations for **HOLD**
    1. Before reviewing change status back to WORK
    2. Review new summary in notes
    3. Move the request forward
